큐·재시도 정책

  • 우선순위: 익스프레스(유료 부스트) > 구독자 > 유료 단건 > 무료. 큐별 워커 플릿 분리(이미지/영상/학습/파기)
  • 재시도: 벤더 5xx·타임아웃 → 지수 백오프 3회. 벤더 장애 감지 시 어댑터가 대체 엔진으로 페일오버(PC-08) — 단, 동일 시드 보장이 불가하므로 잡 메타에 엔진 전환 기록
  • DLQ: 3회 실패 → 데드레터 + 자동 환불 + S12-A 경보. 운영자 원클릭 재실행(무과금)
  • 멱등성: idempotency_key UNIQUE — 재제출 시 기존 잡 반환. hold도 잡당 1회 보장
  • 품질 게이트(Q-01): 요청 컷 수의 1.4배 내부 생성 → 유사도(face embedding cosine)·QC 분류기 통과 상위 N만 exposed=true. 부족 시 1회 추가 생성, 그래도 미달이면 부분 환불 + 사과 UX

크레딧 원장 (돈의 상태기계)

stateDiagram-v2
  direction LR
  [*] --> hold : 잡 접수 (예약)
  hold --> confirmed : 잡 성공 → 확정 차감
  hold --> refunded : 잡 실패·취소 → 자동 반환
  hold --> refunded : 24h 미결 → 배치 강제 반환
  • 원장 규칙: 모든 잔액 변화는 credit_ledger INSERT로만. balance_after는 DB 트리거가 직전 행 기준 검증 — 응용 코드 버그가 잔액을 오염시킬 수 없다
  • hold 구현: credit_holds(job_id UNIQUE, amount, state) + 원장에 hold 행. 가용 잔액 = 원장 잔액 − 활성 hold 합
  • 동시성: 사용자 단위 advisory lock으로 hold 경합 직렬화 (더블 스펜딩 방지)
  • 리컨실(IN-02): 일 배치 — ① 원장 합계 vs 유저 캐시 잔액 ② 지급 합계 vs PG 정산 금액 ③ 24h 초과 hold. 불일치 → 경보 + 자동 티켓
  • 수동 조정(DF-03): reason_code 필수, |delta|>100은 approval_requests 생성 → 리드 승인 시 실행. 데모의 즉시 차단 UX가 이 플로우의 축약형

7.1 프롬프트 조립 (요청 시점, 서버 전용)

// 생성 워커가 호출하는 조립 함수 — 순서가 곧 보안 모델 assemble(job): v = routeVersion(job.theme_id, job.user_id) // ① 버전 라우팅 (카나리 버킷) pos = substitute(v.positive_tpl, { outfit: vocab[job.options.outfit], // ② 어휘 사전 치환 (PC-02) background: vocab[job.options.background], age_style: ageStyle(baby.birthday), // ③ 개월수 자동 주입 (Q-03) }) neg = concat(global_negative, milestone_negative(v.theme), v.theme_negative, SAFETY_LAYER) // ④ 안전 레이어 — 코드 상수, DB 아님 assert lint(pos) == [] // ⑤ 이중 방어: 조립 결과 재린트 return {pos, neg, params: v.model_params, version_id: v.id}
  • ① 카나리 라우팅: hash(user_id + theme_id) % 100 < canary_pct — 같은 사용자는 같은 버전(경험 일관성). 라우팅 결과는 잡에 prompt_version_id로 각인 → 지표 귀속
  • ④ 안전 레이어: DB가 아닌 배포 아티팩트 상수 — 콘솔·DB 어느 경로로도 수정 불가(PC-04). 변경은 코드 리뷰 + 배포
  • 자동 승격 잡: 15분 배치 — 카나리 표본·지표 집계(잡→베스트컷 선택 이벤트 조인) → 표본 ≥200 & 유의성(2-proportion z-test) → 트랜잭션으로 live 교체 + 경보 + 감사
  • 열화 감지(PC-09): live 버전 선택률 24h 이동평균 −10%p → 경보. −20%p → 직전 archived로 자동 롤백 옵션(설정 가능)
  • 상태 전이 무결성: 전이는 저장 프로시저 promote_version() 등으로만 — 트랜잭션 안에서 "live 정확히 1행" 제약과 함께 원자적 교체

시스템설계
